# 2026-07-23 — Remote Ollama on mari: tunnel, probes, first 27B run

## What was done

- **Moved LLM inference to a remote GPU server** (`mari.dinfo.unifi.it`, SSH port 25746, user `ollama-server`) owned by a collaborator. Zero code changes: an SSH local port forward makes the remote Ollama appear at `localhost:11434`, which is what all runners, the pre-flight hook, and the analysis suite already target.
  ```
  ssh -N -f -p 25746 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
      -L 11434:localhost:11434 ollama-server@mari.dinfo.unifi.it
  ```
  Local Ollama must be stopped first (port clash). Qdrant stays local.
- **Offline verification (per verify-first rule)**: 3 probes through the tunnel — models list, plain chat, structured tool call — all passed on `qwen3.5:0.8b`, then repeated on `qwen3.6:27b`.
- **Remote models installed**: `qwen3.6:27b` (collaborator), `nomic-embed-text` (pulled remotely via `/api/pull` through the tunnel — required for the Qdrant experience-embedding path), `qwen3.5:0.8b` (kept for wire tests).
- **Model profiles added** (`config/model-profiles.yaml`): `qwen3.5:0.8b` and `qwen3.6:27b`, both `ollama_native` + thinking.
- **27B envelope probe-validated**: ctx 12288 / maxTokens 6144 → CPU spill stays at 1.0 GB (same as ctx 4096), 21.6 tok/s generation. mari's two GPUs give ~18–19 GB combined usable VRAM; the Q4 27B never fully fits, ~1 GB always on CPU.
- **GPU hygiene** (collaborator's machine is shared; requirement: nothing resident after runs): new `scripts/ollama-gpu.sh [status|evict]`; every simulation launch now chains `; scripts/ollama-gpu.sh evict`. Verified clean after both runs.
