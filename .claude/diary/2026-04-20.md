### Finding 4 — qwen3.5 + grammar is unusable

# Phase 1.5 — Multi-provider chat infrastructure + Ollama native endpoint (closed 2026-04-20)

## What was done
- Root-cause analysis of the 25-agent historical run transcripts: 62% of no-tool-call failures were "model emitted tool call in message.content instead of message.tool_calls" — a shim translation artifact for qwen3.5's training format.
- Offline probed Ollama's native `/api/chat` endpoint (5 probes): `message.thinking` clean, `tool_calls` reliable, `format` grammar + thinking coexist, `options.num_predict` caps output, `done_reason` exposed.
- Built `OllamaNativeChatRequest` + `OllamaNativeChatResponse` (new wire-format pair, ~400 LOC).
- Consolidated `OpenAiChatRequest`+`LmStudioChatRequest` → `OpenAiCompatChatRequest`; same for response. Kept the LM Studio version's bug fixes (empty tool-call-list guard, `getOrDefault(false)`).
- Shrunk `BackendType` enum from 4 values to 2: `OPENAI_COMPAT` (OpenAI API, LM Studio, Ollama shim, vLLM, llama.cpp, LocalAI) and `OLLAMA_NATIVE`. Each carries a `defaultPath()` and `AuthScheme` (BEARER | NONE).

Fix: `ChatCompletionClientImpl` now uses `config.isEnableThinking() || userMessage.ifEnableThinking()` — profile is authoritative, message flag still allowed to force-enable. Applied to both `query()` overloads.

## Decisions made
- Hard break on the enum rename — no backward-compat aliases for `LM_STUDIO`/`OLLAMA` (lab repo, no external config XML consumers).

  - Run A (no thinking, 9 LLM calls): 9/9 clean tool_calls, 0 wrong-box events, 0 retries, 0 failures.

# Persona prompt reframe + context window plumbing (closed 2026-04-20)

## What was done
- **Check 1 — measured Run B truncation.** Parsed `output/siouxfalls-qwen3.5-T0.3-N4096-reasoning/llm_chat_log_ChatLog_combined.jsonl`. All 3 rounds reported `prompt_eval_count=4096` against an estimated input of ~5600 tokens (messages + plan JSON + tool defs). Truncation ratio **0.73×** — Ollama's implicit `num_ctx=4096` was dropping ~27% of the prompt, tool definitions alone already exceeded the ceiling.
- **Check 2 — discovered a second latent prompt bug.** Peeked at the system message Run B actually sent and found the "system prompt" was literal Java source code with escaped `\n` and `\"` sequences ("public static final String systemPrompt =\r\n   \"You are an AI agent...\"). The model had been reading pseudo-code instead of rules for the life of the project. `chatGPTSystemPrompt` content re-authored as clean `planReconstructionSystemPrompt`, rename carried through all call sites.
- **Context window plumbing (pre-flight).**
  - `LLMConfigGroup.contextWindowTokens` field (default 8192), `@StringGetter`/`@StringSetter`.
  - `ModelProfile.contextWindow` record field, parsed by `ModelProfileLoader`, applied by `ModelProfileApplier`. Default 8192.
  - `IChatCompletionRequest.serializeToHttpBody` signature extended with `int contextWindow`.
  - `OllamaNativeChatRequest` emits `options.num_ctx` only when `contextWindow > 0`; `OpenAiCompatChatRequest` accepts the arg but ignores it (OpenAI-compat has no per-request knob).
  - `ChatCompletionClientImpl` passes `config.getContextWindowTokens()` on both `query()` overloads.
  - `IterationStats.thinkingTokenCapHit` added + rolled up in `compute()` (was the one missing field from the earlier 1.5 close-out).
  - `RunSiouxFallsLLMAgents` gets `--context-window` and `--prompt-variant` CLI options; `--prompt-variant persona` tags the output dir.
  - Unit tests: `OllamaNativeChatRequestTest` (3 cases asserting `num_ctx` emit / skip / `think` flag); `ModelProfileLoaderTest` extended with `contextWindow` parse + default-fallback.
- **Persona prompt (Approach 1 — flag-gated, in-file).**
  - `IndividualPrompt.personaSystemPromptTemplate` — first-person template with `{{personaLines}}` placeholder.
  - `IndividualPrompt.personaTaskPrompt` — short user-message lead-in.
  - `prompts.PersonaPromptBuilder` renders MATSim person attributes (`sex`, `age`, `car_avail`, `employed`, `hasLicense`, `bikeAvailability`) into the "Who you are" block. Missing attrs silently dropped.
  - `LLMConfigGroup.promptVariant` field (default `legacy`). `LLMReplanningStrategyModule.buildSystemMessageForVariant` + `buildUserPromptForVariant` select persona vs legacy per run.
  - Legacy `chatGPTSystemPrompt` renamed to `planReconstructionSystemPrompt` + content cleaned of escape artifacts; `chatGPTPlanExtractionPrompt` → `planReconstructionTaskPrompt`.

## Decisions made
- Rubric regex (comparison / attribute / constraint / counterfactual) tightened to exclude plan-data timestamps ("25315.0 sec" endTimes) and hedging verbs ("could", bare "if"). With the new detectors, Run B's legacy reasoning scores **0/12** axes (was flattering 2/3 under the loose regex).
- Sioux Falls persons only expose `sex`/`age`/`car_avail`/`employed` — thin but sufficient as a first-pass persona. Additional attributes (license, bike) handled in the renderer for portability.
- `SimpleRequestMessage` thinking-flag bug (fixed earlier in Phase 1.5) intersects with persona flow: profile authoritatively sets `enableThinking`, message-level `enableThinking=true` can force-enable.
- Context window default raised to 8192 (Phase 2 target). 12288 was too aggressive for RTX 3080 Laptop 16GB with reasoning enabled — timeouts observed.

## Key findings
- **qwen3.5 + persona prompt emits first-person reasoning with attribute reference.** Best round from the 5-agent persona run (agent 9285_1, 58-year-old woman, employed):
  > *"Wait, that's strange. The summary says I don't have a driving license, but the original plan shows me driving a car."*
  > *"I'm a 58-year-old woman who works, but I don't have a driving license. The plan shows me driving a car... So I need to reorganize this plan to use public transport instead. Morning trip: Walk to stop (1603 seconds = ~27 minutes), then PT (322 seconds = ~5 minutes), then walk to work..."*
- **Multi-tool deliberation emerges without being prompted for it.** 6 rounds × 7 tool calls for a single agent (Run B was 1 round × 1 call). Sequence: `activity_chain_summary` → `available_modes` ×2 → `router_tool` ×2 → `validate_timing` → `extract_plan`.
- **Context window fix is measurably live on the wire.** All persona-run requests sent `num_ctx=8192`; `prompt_eval_count` ranged 4515–6829 (no cap). Run B had been silently truncating at 4096.
- **Voice ratio** first-person tokens per 1000 chars: Run B 7.1, persona 7.9 — similar. What shifted was the *content* of first-person statements: from "I can see the original plan has activities" (AI-assistant voice) to "I'm a 58-year-old woman who works" (person voice).
- **Reasoning depth** 2.6× more chars in persona (15971 vs 6026 total across runs), and the persona reasoning refers to attributes, compares modes, questions the plan, and reorganizes with stated reasons.

## Issues encountered
- **10-minute Ollama read timeout hit at `num_ctx=12288`.** Agent prompts aren't unreasonably large (5-7K input), but generation throughput on the RTX 3080 Laptop drops sharply when VRAM pressure forces CPU offload. Dropping to `num_ctx=8192` resolved it.
- Only 1 of 5 requested agents actually replanned — the rest either had `planElements.size() <= 3` (home-leg-home shortest path) or didn't pass the probabilistic strategy selection. Not a persona-run problem; upstream replanning filter.
- Second-round voice in the successful agent drifted to third-person ("The person starts at home at 7:01 AM") before recovering to first-person from round 3 onwards. Prompt could lean harder on "always speak as yourself".

## Next steps
- **Prompt iteration:** strengthen first-person discipline in the persona template (add explicit "speak as yourself at all times, never as a narrator" line; short + high-leverage).
- **Scale test:** 3 seeds × 5 agents × qwen3.5 persona at `ctx=8192`, see whether the first-person emergence is consistent or seed-dependent. GPU budget: ~3 hours serial, RTX 3080 Laptop should handle.
- **Phase 4 readiness:** comparison tools (`compare_routes`, `evaluate_plan`, `suggest_modes`) now become the natural next expansion — the agent already compares modes implicitly, making it a first-class tool with numeric grounding is a measurable step up.
- **Rubric library:** the regex-based audit consistently under-counts persona reasoning. A transcript-level LLM judge pass (qwen3.5 scoring qwen3.5) would be more honest.

## Open questions
- Should the persona template include `age_cohort` language ("middle-aged", "senior") to cue further persona associations, or do we trust the bare integer `age` to be enough?
- Is first-person drift into third-person across rounds (as seen in round 2) a stable pattern or a one-off? Needs the 3-seed scale test to answer.
