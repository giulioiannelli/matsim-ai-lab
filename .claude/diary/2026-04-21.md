## Decisions made

- **Dropped `suggest_modes`** from the Phase 4 plan after T0 recon. `AvailableModesTool` (2026-04-14, in-house) already checks license, car-availability, bike-availability, and vehicle-location chaining. A second tool would have produced near-identical output under a different name.
- **Kept both comparison tools under a single flag** (`comparisonToolsEnabled`) rather than a per-tool flag. They are meant to be reasoned about together; splitting the switch would only create more configurations to test.
- **Prompt stays in `IndividualPrompt.java`** rather than migrating to a filesystem layout. The original plan's Phase 3 (FS versioning) remains deprioritised; Phase 4 uses an addendum pattern instead.
- **`modes` argument is a comma-separated string**, not a list DTO. No new DTO type was worth adding for one argument — the LLM handles CSV natively, and the empirical quoted/bracketed variants got handled in `parseModes` during smoke-sim debugging.

## Key findings

- **Both comparison tools fire on qwen3.5-persona** without prompt coaching beyond the addendum. The 11-round smoke transcript shows the model reaching for `compare_routes` to evaluate `walk,pt,bike` when the person's car/bike availability was already established by `available_modes`.
- **Tool inter-operation is emergent**: the model called `evaluate_plan` on the as-survey plan first, saw totals (2 legs, 449s, mode=car), then called `available_modes` — discovered the car isn't actually usable (no license) — then called `compare_routes` for `walk,pt,bike`. That sequence is the kind of reasoning the tools were designed to invite.
- **pt came back with real numbers** (1935s / 2354 m / 2 transfers) on the smoke; walk and bike came back infeasible because of an LLM quoting quirk (see Issues).
- **`evaluate_plan` totalDistance was NaN** when the survey plan's route object had an uninitialised distance. Fixed by a NaN guard.

## Issues encountered

- **Two CSV header writes, only one edit**: `setUpLogger` writes the header twice (iter file + combined file). My first `replace_all=false` edit only updated the iter header; the combined CSV was still written with 21 columns. Caught on the first smoke run when `comparisonToolInvocations` was missing from the combined CSV. Fixed by adding the column to the second header-write site.
- **LLM wraps `modes` in outer quotes**: qwen3.5 emitted `"walk,pt,bike"` (literal quotes around the whole CSV). The original `parseModes` split on `,` and ended up with `"walk` and `bike"` — both rejected as unsupported modes. Fixed by stripping per-item quotes, optional JSON-array brackets, and any remaining stray quote chars. Added `ParseModesTest` with four shapes (quoted, per-item quoted, JSON-array literal, single-quoted).
- **NaN distance propagation** in `EvaluatePlanTool`: MATSim survey plans sometimes have un-routed legs whose `route.distance` is NaN. `totalDist += NaN` poisoned the whole total. Fixed with a NaN guard on both travelTime and distance.
- **Stale-class illusion on the first smoke**: `exec:java` ran after `compile` and still emitted a 21-column header. Root cause was actually (1) above — the bytecode was up to date, but the combined header-write site wasn't. Initially misdiagnosed as a classpath-cache problem.
- **Sim throughput is bottlenecked by LLM latency**, not anything Phase 4 changed. The 50-agent smoke didn't finish in ~12 min because Ollama took ~minutes per round; killed manually after getting sufficient evidence from the JSONL.
