# Plan DTOs — MATSim Plan ↔ JSON

> **Source files**: `matsimdtobjects/PlanDTO.java`, `ActivityDTO.java`, `LegDTO.java`, `*RouteDTO.java`

## What are DTOs?

Data Transfer Objects — plain Java classes that carry data between MATSim (rich Java objects) and the LLM (JSON strings). They strip away MATSim's complexity and expose only what the LLM needs.

## The DTO hierarchy

```
PlanDTO
  └── elements: List<PlanElementDTO>
        ├── ActivityDTO (type, facilityId, linkId, endTime)
        └── LegDTO (mode, routingMode, departureTime, travelTime)
              └── route: RouteDTO
                    ├── NetworkRouteDTO (car/bike: startLink, endLink, linkIds)
                    ├── TransitPassengerRouteDTO (PT: stops, line, route, departures)
                    └── GenericRouteDTO (walk: distance, travelTime)
```

## Conversion: MATSim → JSON

```java
// In LLMReplanningStrategyModule.finishReplanning()
String basePlan = PlanDTO.toDTOFromBaseObject().apply(plan).toJsonObject(gson).toString();
```

## Conversion: JSON → MATSim

When the LLM calls `extract_plan`, the tool receives JSON and reconstructs a MATSim Plan:

```java
// ExtractPlanTool.callTool()
PlanDTO planDTO = gson.fromJson(planJson, PlanDTO.class);
Plan matsimPlan = planDTO.getPlan();  // Converts back to MATSim objects
```

## Activity types and validation

`ActivityDTO` validates that activity types are from an allowed set:
- Real activities: `home`, `work`, `education`, `shop`, `leisure`, `errands`, `other`
- Interaction activities: `pt interaction`, `car interaction`, `bike interaction`

Interaction activities are intermediate stops in a trip chain (e.g., waiting at a PT stop). The LLM should not create or modify these directly — they're generated by the router tool.

## Route types

| Route type | Used for | Key fields |
|-----------|----------|------------|
| `NetworkRouteDTO` | car, bike | startLinkId, endLinkId, intermediate linkIds |
| `TransitPassengerRouteDTO` | PT | accessStop, egressStop, lineId, routeId |
| `GenericRouteDTO` | walk, fallback | distance, travelTime |

The route type is discriminated by the `routeType` field in JSON, enabling polymorphic deserialization.

## Where to refine

- **Simplify PT plans before sending to LLM**: Collapse walk→pt interaction→pt→pt interaction→walk into a single "PT trip" representation. This reduces reasoning time significantly.
- **Add computed fields**: Travel time summary, mode chain summary, total distance — things the LLM currently has to compute from raw data.
